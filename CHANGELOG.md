# Changelog

All notable user-facing changes are recorded here so GitHub Releases can use curated, public plugin release notes instead of only autogenerated merge summaries.

The release workflow expects a versioned section named `## [X.Y.Z]` for tag `vX.Y.Z`. Keep issue-closing keywords out of changelog entries; link pull requests directly and handle issue attribution or closure in separate issue-triage work.

## [Unreleased]

## [0.1.2] - 2026-08-23

### Security

- Hardened Chromium controller state, private file handling, lock ownership, CDP WebSocket validation, and bounded CDP responses so the helper treats Chromium's loopback DevTools listener as unauthenticated local IPC. ([PR #31](https://github.com/HackXIt/omarchy-chromecast/pull/31))
- Treated receiver names and helper override values as untrusted input: Quickshell now consumes structured JSON target data, target names render as plain text, ambiguous duplicate receiver names are rejected, and unsafe helper overrides fall back to the bundled helper. ([PR #31](https://github.com/HackXIt/omarchy-chromecast/pull/31))

### Fixed

- Detects and cleans stale or orphaned `chromium-castctl` profile browser instances when controller startup is interrupted or state is missing, while keeping `status` and `doctor` honest. ([PR #31](https://github.com/HackXIt/omarchy-chromecast/pull/31))
- Stops active casts and closes the isolated Chromium control browser more reliably, including cases where an individual Cast stop request fails. ([PR #31](https://github.com/HackXIt/omarchy-chromecast/pull/31))

### Changed

- Expanded lifecycle and security regression coverage with dummy Cast backend workflows, pinned GitHub Actions, and release archive checksum validation. ([PR #31](https://github.com/HackXIt/omarchy-chromecast/pull/31))
- Added this changelog as the source for future GitHub Release notes and documented the tag-driven release process. ([PR #33](https://github.com/HackXIt/omarchy-chromecast/pull/33))

## [0.1.1] - 2026-08-23

### Security

- Treated helper output and Chromecast sink names as plain UI text so receiver names are not interpreted as markup or shell syntax. ([PR #17](https://github.com/HackXIt/omarchy-chromecast/pull/17))

### Documentation

- Documented Omarchy plugin removal. ([PR #15](https://github.com/HackXIt/omarchy-chromecast/pull/15))

## [0.1.0] - 2026-08-16

### Added

- Packaged Omarchy Chromecast as a public Quattro shell plugin with manifest validation, CI, screenshots, issue templates, and an initial tag-driven GitHub release workflow. ([PR #11](https://github.com/HackXIt/omarchy-chromecast/pull/11), [PR #13](https://github.com/HackXIt/omarchy-chromecast/pull/13))

### Fixed

- Improved helper lifecycle behavior before the first public release, including empty `PATH` handling, stale target error clearing, browser startup timeout handling, and picker/stale-browser cleanup safety. ([PR #6](https://github.com/HackXIt/omarchy-chromecast/pull/6), [PR #7](https://github.com/HackXIt/omarchy-chromecast/pull/7), [PR #8](https://github.com/HackXIt/omarchy-chromecast/pull/8), [PR #9](https://github.com/HackXIt/omarchy-chromecast/pull/9))
